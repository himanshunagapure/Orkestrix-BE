Phase 1: Impact Analysis — "What Will Break?"

Before any code changes, the system:

1. Maps the blast radius bidirectionally — Follows every arrow in your workflow graph, including:
  - Forward edges (normal flow: A → B → C)
  - Backward edges (retry loops, fallback paths, compensation rollbacks, human-in-the-loop returns)

Node A → Node B → Node C
 ↑         │
 │    (retry)          ← Backward edge detected
 └─────────┘
If Node B changes, Node A is now in the blast radius because a retry sends execution back to it.

2. Detects cycles — Identifies all nodes participating in loops (retry, fallback, saga compensation, user returns)

3. Classifies each change (same as before):
  -  Safe — Only inputs changed, outputs stay compatible
  -  Breaking — Outputs removed/renamed/types changed
  -  Structural — Nodes/edges added or removed
  
4. Shows you a bidirectional report:
▎ "Changing Node B's output schema will affect:
▎ - Downstream: Node C, Node D (normal flow)
▎ - Upstream (via retry loop): Node A (retries back to A with new data shape)
▎ - Fallback path: Node F (error handler receives new error format)"

You decide: Approve or reject. Nothing happens until you say yes.

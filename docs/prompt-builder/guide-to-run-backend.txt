Async build jobs (Phase 1+)

API (agent_new):
  POST /aiqod-agent/agent/agentic/workflow/jobs
  → 202 { jobId, workflowId, jobType, status }
  Poll: POST /aiqod-agent/agent/agentic/workflow/progress  (jobStatus field)

Worker env (langgraph/.env) — ADD only; do not rename existing VALKEY_*:
  BUILD_STREAM_NAME=build_tasks
  BUILD_GROUP_NAME=build_workers
  MAX_BUILD_WORKERS=1
  BUILD_AGENT_BASE_URL=http://127.0.0.1:5010/dev  # agent host+prefix (NOT :8000; include /dev)
  BUILD_PREVIEW_TIMEOUT_SEC=3600               # 1h worker↔agent preview
  BUILD_EXECUTE_TIMEOUT_SEC=10800              # 3h; worker↔agent execute
  BUILD_RESUME_TIMEOUT_SEC=10800               # 3h; worker↔agent resume/sync
  BUILD_CLAIM_TIMEOUT_MS=14400000              # 4h; must exceed longest job
  MAX_BUILD_ATTEMPTS=3                         # stale RUNNING requeue limit

Agent env (backend/.env) — same Valkey host/port as worker so enqueue hits the same broker:
  VALKEY_HOST=localhost
  VALKEY_PORT=6380
  BUILD_STREAM_NAME=build_tasks

Worker code is self-contained under langgraph/ (services/build_job.py, build_execute.py).
Do not point the worker at backend/ — exec deploy does not ship sibling backend/.
Async execute calls agent HTTP POST /plan/execute (long timeout); FE only polls /progress.

Sync endpoints POST /scratch/preview, POST /plan/execute, and POST /workflow/resume are unchanged.
Async: POST /workflow/jobs with jobType preview|execute|resume; worker calls those sync URLs.
